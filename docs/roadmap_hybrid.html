MPC × RL 하이브리드 적용 로드맵

우리 MPC 스택(A안 MPC+WBIC·B·C OCP·MPPI)과 RGA RL 저장소(RobotSW_IsaacLab)를 sim2sim 브리지로 연결해, 전략 리포트의 5패턴(A~E)·Phase(H0~H3)를 실제 코드베이스 기준으로 재계획한다.

✔ 리포트 가정보다 유리한 3가지(실측): ① RL 저장소에 R_Skeleton(=R.pet)·hind_leg(=02_Leg) 로봇이 이미 별도 태스크로 존재(rga.py) → 형태 불일치 블로커 없음. ② 정책 ONNX/JIT export + estimator 번들 + 전용 sim2sim 스크립트가 이미 구현됨. ③ 파쿠르 RMA 관측이 waypoint/heading 조건부 → DTC식 교사 슬롯이 이미 열려 있음.

4 · 우선순위 로드맵 — 무엇을 먼저

Phase 0 즉시 · ~1주 우리 인터페이스 동결 & 확인

  • USD 경로 재지정 — RL 저장소 로봇 에셋이 전부 /home/lgb/IsaacLab/... 하드코딩
  • ✔ 확인됨(2026-07-13): R_Skeleton = velocity-command(vx·vy·yaw-rate) + ActorCriticRMA(파쿠르와 동일 MLP·비순환) — waypoint 아님. 우리 A안 명령(V·VY·WZ)과 정확히 일치 → 브리지 명령 매핑 자명·MPC 교사 자연스러움. 단 policy obs에 참조궤적 슬롯은 아직 없음(AMP는 discriminator/reset 전용). 38-DOF(v0)/34-DOF(v1), 허리·목 포함, PD Kp 100~300
  • RL 동료로부터 메타데이터 계약 수령: obs 차원·순서·정규화(mean/std)·action 스케일·PD 게인·제어주기·decimation
  • A안 MPC+WBIC를 "임의 초기조건 → 궤적" API로 래핑 (리포트 H0)
산출물: 관절 매핑 테이블(단위테스트 고정) · 궤적 포맷 스펙 · R_Skeleton obs 스타일 판정 1장

Phase 1 첫 실전 · ~2–3주 우리 sim2sim 브리지 — Go2 파쿠르로 먼저 검증

왜 Go2 먼저: 오늘 존재하고 export되는 유일한 정책. obs 순서·프레임·PD·estimator를 known-good 벡터로 브리지를 디리스크한 뒤 R.pet로 넘어간다(리포트 H0.5 정제판).

  • python mujoco.viewer + onnxruntime 최소 루프(50 Hz 정책 / 200 Hz PD decimation) → 통과 후 C++ 뷰어 통합
  • Go2 12-DOF MJCF(menagerie) · 명령 슬라이더 + falls/추종 오버레이
함정 6종(실측): obs=46(42 아님, 접촉 4 추가·yaw오차가 채널0–1) · hip action ×0.5 선적용 후 ×0.25 · 관절순서=타입별(다리별 아님) · 속도/중력 body frame · quat wxyz · base 속도는 estimator가 추정(외부 공급 불요) · 조향은 goal-heading(yaw-rate 명령 아님)
산출물: rl_policy_runner(obs빌더+onnx+PD 브리지) · Go2 배포 falls=0(20회) 검증

Phase 2 ~2주 우리 같은 브리지를 R_Skeleton/hind_leg 정책에 적용

  • 실제 로봇 정책을 우리 MuJoCo에 배포(허리·발목 관절 매핑 확장)
  • RL ↔ MPC(A안) 동일조건 나란히 비교 리포트 = §2 상보성의 우리 로봇 실증 데이터
산출물: RL↔MPC 비교 리포트 1장(회복시간·CoT·외란강건·falls)

Phase 3 ~4–6주 우리+동료 MPC 교사 하이브리드 (패턴 A)

  • H1 파일럿(좁은 스킬, sit/getup): gather-seeded MPPI/MPC 레퍼런스 라이브러리 → RL tracking policy → 브리지 배포. 성공지표 명확(bounce 각·falls), 실패해도 궤적 자산 잔존
  • H2 보행 DTC화: A안을 학습루프 내 실시간 레퍼런스 생성기로(이미 50 Hz). 레퍼런스 노출=서브셋만(ptgt·cs·관절목표), 목표 관절각 포함(수렴 결정타), touch-down 이벤트 업데이트→예산 되면 50 Hz
산출물: sit/getup 폐루프 정책 · 보행 tracking 정책(run 프리셋 ~2.18 m/s 목표)

Phase 4 장기 우리 안전 계층 소유 (패턴 D) + 실기

  • predictive safety filter(관절 한계·자세·접촉력)를 RL 출력 위 상시 계층 — MPC 담당만 만들 수 있는 차별화·특허 소재
  • 실기 LowCmd 인터페이스(kp=kd=0, τ 직접) 연동
병렬 트랙(RL 동료 의존 없음, 지금 착수 가능): ① 패턴 C-3 MPC 하이퍼파라미터 자동튜닝(BO/RL) · ② aligator RTI(1–3 iter)+shift warm-start 속도개선(리포트 §9.2) — 오프라인 궤적 생성은 현재 속도로 충분하므로 RL 협업의 선결 조건 아님.
