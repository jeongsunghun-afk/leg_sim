DTC · 계획↔제어

Deep Tracking Control

Jenelten, He, Farshidian, Hutter — ETH Zürich, Science Robotics 9(86) 2024 · arXiv:2309.15462

핵심 — TO 플래너(TAMOLS)가 학습 중 발판 참조(footholds)를 롤아웃하고, NN 정책이 그 발판을 추종하도록 시뮬레이션에서 학습. 보상은 임의 시점의 base 자세가 아니라 touchdown 시점의 목표 발판 위치(위치 기반 추종).

비대칭 actor-critic — critic엔 특권 참값(GT), 정책엔 노이즈 관측만. 정책은 계획 해의 일부(발판·목표관절·접촉스케줄)만 관측 → 모델 오차에 강인. 배포 시 다른 TO·다른 주기로도 zero-shot 추종.

우리에 적용 — 계획층 TO의 p_tgt·cs(발판·접촉타이밍)를 정책 입력 채널로. 비대칭 A-C = 우리 critic 특권입력 구조와 동일 원리.
APT-RL · 다단계 학습

Agile Perceptive Multi-skill Locomotion

Kang, Park, Song, Kim, Hong, Park — KAIST/ADD, Science Robotics 11(116) 2026 · "APT-RL"(skillquad)

3단계 — (i) 표현학습: 2D TO 모션 데이터로 TVAE 학습 → 공유 잠재 + 게이트별 토크 디코더(trot/bound). (ii) RL: 얼린 디코더를 잠재 액션으로 재사용 + 보조 액션, 게이트 선택 로짓, MLP actor + Estimator + Elevation Encoder. (iii) 지각 증류.

지각 증류(stage iii) — 특권 elevation map을 쓰는 교사를, Depth CNN + GRU encoder 학생이 raw depth + 2D LiDAR에서 재현하도록 지도학습. ← 우리 예정 추가의 원형. 실기 4.25 m/s, 낙하 6 m/s.

우리에 적용 — §04 학습 3단계의 골격. §06 예정 Depth CNN·GRU가 정확히 stage iii 구조.

★우리 스택의 좌표 — 국면별 게이팅

꼭짓점 하나가 아니라 삼각형 안을 국면별로 이동. 승자 미정 상황에서 가장 방어적인 포지션.

  • 평상시 = APT 꼭짓점 (단일 정책·잠재 스킬·온보드 지각·암묵 발판)
  • 정밀 국면 = APT–Raibo 변의 DTC 지점으로 게이팅 이동 (p_tgt·cs 참조 조건화)
  • 자율 보강(옵션) = PUMA 변의 발판 prior 특징 차용 (게이팅 OFF 시 정밀도↑, 구조 충돌 없음)
  • Raibo 차용 = capability-aware 필터(계획이 정책 능력 밖을 요구 안 하게) + 경쟁적 CVAE 커리큘럼(soft·클러터 난이도 자동조절)
  • soft 표면(쇼파·침대) = DTC 게이팅 반드시 OFF — 강체 TO 참조는 오도. 물성 랜덤화 RL 영역
★실증(quad17 DTC 트랙, 2026-08) — DTC 발판참조 = task-dependent 샘플효율 레버(점근성능 아님)
위 게이팅 철학을 17-DOF quad에서 통제실험으로 검증했다. DTC-ON=offline TAMOLS 캐시(full-TAMOLS 발판·base·접촉을 롤아웃서 조회) vs DTC-OFF=heightmap-RL(같은 지형관측, 발판참조만 제거), 동일 3D 지형·명령균등·2-seed.
  • 정밀지형(계단) — DTC가 학습을 크게 가속: 동일 iter4000서 지형레벨 base 1.15 → DTC 4.99(≈2–3배 빠른 난이도 도달). 단 끝까지(iter10000) 학습하면 둘 다 ~6.4로 수렴 — 최종성능은 동률. → DTC 이득은 샘플효율이지 최종 capability가 아님.
  • 관용지형(평지 갭) — 반대로 캐시가 방해: 고정 발판참조보다 RL 창발(capture-point 반응)이 이긴다.
결론 — 모델기반 발판유도는 정밀지형서 "빠르게 배우는" 레버(점근성능 향상 아님)이고, 관용지형선 오히려 해가 될 수 있다. 이것이 §03 국면별 게이팅(정밀=ON·관용/soft=OFF)의 실측 근거다. 상세=DTC_개발리포트.md §P2.7.

05 모듈 카탈로그 — 실제 구축된 정책 내부 (ActorCriticRMA)

이번 세션의 정책은 rsl_rl 포크 ActorCriticRMA다. 아래는 각 모듈이 무엇을·어떤 신경망으로·무엇으로 학습·배포되는지. 핵심은 배포 모듈(actor·history_encoder·estimator)과 학습전용 모듈(critic·priv_encoder·참 특권정보)의 분리 — RMA 교사-학생의 뼈대다.

왜 분리하나 — 실기엔 마찰·질량·외력 같은 특권정보가 없다. 그래서 학습 땐 교사(priv_encoder)가 참값으로 잠재를 만들고, 학생(history_encoder)이 관측 이력만으로 그 잠재를 재현하도록 지도학습한다(RMA). 배포는 학생만. critic의 특권입력(비대칭 A-C)은 학습 신호를 정확하게 하되 배포엔 안 나간다 — DTC와 같은 논리.
지형 채널 2겹 — Elevation Encoder(scandot_encoder, 특권 heightmap → z∈R³²)가 교사 지형 채널이고, 예정 Depth CNN+GRU가 raw depth에서 그 z를 증류하는 학생이다(APT-RL stage iii와 동형). 단 현재 우리 biped flat-foot는 blind(num_scan_obs=0 → scan_latent=0)로 이 채널이 비활성 — 위 2점 보행은 순수 자기수용(proprio) 결과다. 지형 지각을 켜는 시점에 Elevation Encoder(교사)를 활성화하고 Depth CNN+GRU(학생)를 증류한다.

  • 목·몸통 raw depth를 정책 내부 CNN이 직접 인코딩 → 명시 TerrainMap(heightmap) 대체.
  • 매핑 지연 없이 지형 인지가 end-to-end로. 목 depth의 사각 봉합도 직접 반영.
  • 학습 = 교사 Elevation Encoder의 지형 잠재 z를 지도학습으로 증류(정책·교사 freeze).
raw depth → CNN → 정책  (≈ TerrainMap 대체)

🔜 GRU encoder

고정창 1D-CNN → 순환 메모리

  • 현 history_encoder(1D-conv, 10프레임 고정창) 대신 가변 시계열 메모리.
  • 접촉/외란 적응·상태추정을 순환 상태로 강화 → RMA 잠재 추정을 GRU로.
  • APT-RL에서 Depth CNN과 한 인코더(CNN-GRU)로 묶여 지각 증류에 동시 학습.
history → GRU → 잠재  (≈ history-CNN 대체)

07 지형 경로 A vs B — 무엇을 만들고 무엇을 배포하나

지형 잠재 z를 정책에 넣는 경로가 둘이다. 대등한 선택지가 아니라 "교사 → 학생" 의존 관계 — B는 A의 z를 증류해서 배우므로 A 없이는 못 만든다. 둘의 시작점(raw depth)은 같지만 출력·소비자가 다르다.

경로 A모듈형 (교사이자 최소 배포)— 명시 높이맵 경유
raw depth──▶ TerrainMap──▶ 높이맵──▶ Elevation Encoder──▶ z∈R³²──▶ actor
학습 vs 배포 — 학습(교사) 땐 앞단 raw depth→높이맵이 특권 직접조회(mj_ray)로 대체된다. 즉 sim의 scandots = 특권 높이. 배포 A는 앞단에 실제 TerrainMap 매핑이 붙어야 성립. 뒷단 Elevation Encoder = 우리 코드 scandot_encoder(MLP [128,64,32]→z).
현재 우리 biped는 이 경로 비활성 — num_scan_obs=0 → scan_latent=0. 지금 2점 보행은 z 없이 순수 proprio. 1단계 = 이 A를 켜는 것(scandots obs 추가).
경로 Bend-to-end (선택적 상위단계)— raw depth 직행
raw depth─────▶ Depth CNN + GRU─────▶ z∈R³²──▶ actor
A를 흡수 — 명시 높이맵 단계를 생략하고 raw depth에서 z로 직행. 입력측은 TerrainMap과, 출력측은 Elevation Encoder와 닮음. 학습 = A(교사)의 z를 지도학습으로 증류(정책·교사 freeze) → A 없이는 못 만듦.
왜 얹나 — 매핑 지연·드리프트 제거, 매핑 실패(얇은 장애물·반사면) 대응. 단 출력이 잠재라 계획층(TO·STGN)은 못 씀 → 배포 후에도 명시 TerrainMap은 항법용으로 별도 유지(역할분담).

단계별 로드맵 — A부터, B는 필요 시

A는 어느 경로든 필수(교사로도 최소 배포로도). B만 단독은 불가.

현재 · blind
A·B 둘 다 없음, proprio만. 2점 평발 보행이 여기 — 지형 채널 scan_latent=0.
1단계 · A
A 구축·배포 → 지형지각 확보. Elevation Encoder 켜기(num_scan_obs>0). 여기까지면 지형 보행 됨.
↓ 실기서 매핑 지연/드리프트가 문제되면
2단계 · B
B 증류 추가 → 배포는 B로 교체. A(교사)→Depth CNN+GRU(학생). 선택적 상위단계.
한 줄 — A는 필수(교사이자 최소 배포), B는 A 위에 얹는 선택(교사 A 없인 못 만듦). "둘 중 하나"라면 답은 언제나 A부터. 우리는 아직 0단계(blind)라, 지형지각을 켠다면 첫 목표는 A 활성화.

용어·기호가 뜻하는 것

위 카드의 입력→출력에 나오는 말들.

proprio (자기수용 관측)로봇이 자기 몸을 느끼는 값 — 관절 위치·속도(엔코더) + 몸통 자세·각속도(IMU) + 직전 액션. 실기에서 항상 있다.
정책 obs (policy observation)Actor(정책 신경망)에 실제로 들어가는 입력 벡터 전체 = proprio + 추정잠재 z + (발판·명령). 즉 "정책이 보는 것".
특권정보 (privileged)sim에선 알지만 실기엔 없는 값 — 마찰계수·질량·외력·정확한 지형. 교사가 쓰고, 학생이 관측만으로 흉내낸다.
잠재 z (latent)특권정보·지형을 신경망이 압축한 작은 코드(예: 20~32차원 벡터). 정책이 이 z 하나로 "지금 환경이 어떤지"를 안다.
v̂ (base velocity 추정)로봇은 자기 몸통 속도를 직접 못 잰다(가속도계만 있음) → 관측에서 추정. 보행 제어에 필수.
τ (tau · 제어 출력)각 관절에 줄 힘(토크) 또는 목표각. 로봇이 실제로 받는 명령 = 정책의 최종 출력.
ψ (psi · 지형 파라미터)CVAE에서 stepping stone 배치를 정하는 6D 숫자(간격 r·방향 θ·기울기 tilt…). 이걸 바꾸면 지형 난이도가 바뀐다.
heightmap로봇 주변 지형 높이 격자(2.5D). 어디가 높고 낮은지 = 지형 인지의 원천.

각 모듈이 하는 일 (비유로)

신경망 하나하나가 왜 있고 무슨 역할인지.

모듈비유하는 일
Actor (정책 π)두뇌obs를 받아 "지금 각 관절을 어떻게 움직일지(τ)"를 결정. RL로 보상 최대화 학습. 유일하게 로봇을 실제로 움직인다.
Critic코치"이 상태가 얼마나 좋은지(가치 V)"를 평가해 Actor 학습을 도움. 학습에만 쓰고 로봇엔 안 실림.
priv_encoder교사(내부)sim의 특권정보(마찰·질량)를 잠재 z로 압축 → Actor가 환경을 앎. 실기엔 특권이 없어 배포 못 함.
Elevation Encoder교사(지형)특권 heightmap을 지형잠재 z로 압축. 지형 인지의 교사(학생 Depth CNN의 정답).
Estimator속도계못 재는 몸통 속도 v̂를 관측에서 추정(참 속도에 회귀). 배포.
history_encoder학생(적응)과거 10프레임 관측만으로 교사(priv_encoder)의 z를 흉내내도록 학습(증류). 실기에선 이게 특권정보를 대신. 배포.
Boundary estimator충돌 예측기발판 계획 때 "이 경로로 가면 지형에 부딪히나"(충돌 최저경계)를 예측 → planner 필터. 롤아웃 없이 빠르게.
Depth CNN학생(눈)raw depth 카메라 영상에서 지형잠재를 직접 뽑음(Elevation Enc z 흉내). 명시 heightmap 없이 배포.
GRU encoder학생(기억)관측·영상 시퀀스를 순환 기억으로 압축(고정창 1D-Conv 대신 가변 시계열).
CVAE map generator지형 출제자지형(ψ)을 생성. tracker가 넘어선 지형을 배워 조금 더 어려운 지형 출제(경쟁 커리큘럼). 로봇엔 안 실림.
TVAE스킬 사전TO 모션 데이터를 잠재 스킬 라이브러리로 압축(사전학습). APT가 재사용하는 스킬.

09 액추에이터 정합 — PACE (배포 직전 sim2real)

정책이 sim에서 잘 걸어도, 실모터의 반사관성·마찰·지연이 안 맞으면 실기서 무너진다. PACE(ETH RSL)로 실측 데이터에서 액추에이터 파라미터를 식별(system-ID)해 sim 모터모델을 실기에 맞춘다.

무엇을 식별하나

  • PaceDCMotor = DCMotor + encoder_bias + DelayBuffer.
  • CMA-ES로 관절당 4N+1개 식별: armature(반사관성)·점성/쿨롱 마찰·엔코더 바이어스 + 지연.
  • 입력 = chirp_data.pt(가진 실측). 우리 #1 sim2real 갭(로터관성·기어마찰·감쇠) 정조준.

검증 현황

±2.1%
armature sim2sim 복원 오차
+6.5%
지연 주입분 복원
미검증 — sim2sim 파이프라인만 통과. 실물 데이터(chirp 가진)로의 식별은 하드웨어 확보 시. 그전까진 armature 기본ON 등 물리적 수단만 사용(비물리 상태절단 금지).

10 보강 로드맵 — Hwangbo 2019 대조서 도출

계보의 Hwangbo 2019와 대조하면 정책 아키텍처는 이미 넘어섰고(RMA·estimator·GPU 4096) 진짜 구조적 갭은 ①actuator net 한 곳. 나머지 ②–⑤는 조건부 후보(지금 필수 아님) — 정직하게 "새 제안 vs 기존 계획", "언제 값어치"를 구분한다.

#보강기존 계획?언제 값어치 / 근거 논문우선순위
① actuator net / 실측 액추에이터 IDreality gap의 지배 요인 기존 계획 (우리 #1 갭) 배포 전 필수. 02_Leg 실측(chirp) 필요. 깨끗한 감속기=PACE 파라메트릭 충분 / backlash·지연 크면 actuator net. Hwangbo 2019 필수·대기
② 낙상복구 RL 스킬동적 self-righting 새 제안 (현 복구=모델기반) 조건부 — 워커가 자주 넘어질 때만. Hwangbo 2019 · Miki 2022 선택
③ 효율 보상 + 곧은무릎 자세토크/전력 최소화 자세=진행중(재균형#4) · 효율=새 제안 자세는 지금. 효율 보상항은 조건부(배터리/발열시). Hwangbo 2019(곧은무릎=효율↑, RL만 활용가능) 일부 진행중
④ 온보드 추론 예산ActorCriticRMA가 무거움 기존 계획 (배포 체크리스트) 배포 루틴 — 그때 검증. Hwangbo=25μs/추론 강조 배포시
⑤ RMA 복잡도 정당화 → 지각 켜기blind엔 과설계 기존 계획 (경로 A/B) 관찰(행동 아님). 해법=Elevation Encoder/Depth CNN 켜기 = §07 로드맵. Lee 2020 · Miki 2022 · APT 2026 계획됨
정직 요약 — 당장 로드맵에 새로 넣을 필수 항목은 없다. ①(actuator 실측)은 이미 #1 갭이고 하드웨어 대기, ⑤(지각 켜기)는 이미 §07 계획. ②·③효율은 순수 신규 후보로, 그 문제(잦은 낙상 / 배터리·발열)가 실제 나타나면 그때 얹는다. 지금 순서 = 재균형#4 자세개선(③자세) → 액추에이터 실측(①) → 지각(⑤), 최종 = APT.
