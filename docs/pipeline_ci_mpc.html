02_Leg · 17-DOF · 모델기반 제2트랙

Contact-Implicit MPC 파이프라인

험지(gap·stepping) 크로싱의 근본 한계인 고정 접촉 스케줄을 넘기 위해, 접촉 모드·발판·타이밍을 온라인으로 동시에 발견하는 CI-MPC를 설계·구현한다. 배포 컨트롤러(A: WBIC+MPC)는 불변이며, 이는 병렬 연구 트랙이다.

스택 Crocoddyl · Pinocchio · MuJoCo/MJX(GPU)  ·  코드 simulation/quad/ci_mpc/  ·  참조 Kim et al. 2023, Contact-Implicit MPC (KAIST HOUND)

01 왜 필요한가 — 고정 스케줄의 벽

타이밍을 결정변수로 못 올리면 지형 간격에 스텝을 맞출 수 없다

현재 컨트롤러 A(WBIC+SRBD MPC)·B(centroidal)·C(fulldynamics)는 모두 접촉 스케줄 (T_ds/T_ss)을 고정 입력으로 두는 fixed-schedule이다. 발 cadence·step length가 지형 간격과 우연히 맞는 gap만 넘는다 — 속도-공명(speed resonance). selectFoot(③)은 발판 위치만 nudge할 뿐 타이밍은 못 바꾼다.

타이밍을 최적화하려면 접촉 on/off가 결정변수가 되어야 하는데, 그러면 문제가 비볼록(이산/상보성)이 되어 실시간 볼록 QP가 깨진다. 이 벽을 넘는 두 갈래 = 모델기반 CI-MPC 또는 RL. 지형 이산 발판 탐색은 RL 피벗을 유지하고, 본 트랙은 접촉 모드 창발을 담당한다.

롤아웃 각 노드에서 누적. 전진 추종이 주목표, 나머지는 붕괴/이탈 억제

붕괴 barrier1500z < 0.32주저앉음 하드 차단
soft floor400max(0, 0.34 − z)²높이 하한 부드럽게
★ 형상 교훈. 높이를 추종(z−z*)²으로 벌하면 보행의 자연 bobbing이 억압돼 MPPI가 얼어붙는다. 그래서 높이는 추종이 아니라 붕괴 barrier + soft floor로만 두고, 전진을 우세하게 둔다. MPPI 갱신: w = exp(−(c−β)/λ) (λ=40) 가중평균 → 시간축 스무딩. 매 틱 iters 2회, warm-start로 소수 반복.

07 걷게 만든 핵심 발견

stance 유지

KP=300 + IK 높이 0.42

PD는 base 중력 피드포워드가 없어 sag한다. IK를 목표+sag만큼 높게 잡고 KP를 올려 stance 유지(KP≥600은 진동).

전진 추진

전진 트롯 gait-prior

스탠스 발을 몸기준 뒤로 sweep(추진)·스윙 발 앞착지. "제자리" prior는 뒤로 표류한다. 물리가 실제 접촉을 결정.

cost 형상

height 추종 제거

높이 추종항은 보행의 자연 bobbing을 벌해 MPPI를 얼린다. 붕괴 barrier + 전진 우세만 두니 크라우치 없이 전진.

미해결 긴장

fast ↔ stable

vx 가중↑ → 크라우치-다이빙 착취(z0.18 낙상). prior가 ~0.12만 안정 지원. 완전 속도엔 긴 스텝 prior + 정교한 shaping 필요.

08 GPU 인프라 (MJX)

CPU 순차 롤아웃(740ms/스텝)은 튜닝 비현실적 → GPU 병렬화

  • RTX 4060 + jax[cuda12] + mujoco-mjx 3.9.0 (proxddp env).
  • ★ 메쉬 충돌 스트립이 결정적 — 몸통 메쉬 충돌을 끄고 발 sphere + 바닥만 충돌시키면 MJX forward JIT 컴파일이 256초 → 8초. (strip_mesh_collision)
  • 전체 롤아웃을 단일 JIT(lax.scan H×sub) + vmap(Nsamp)로 묶어 GPU 병렬.
  • 반사관성(armature)이 폐루프 안정의 전제 — MJCF의 dof_armature=0이면 stiff PD가 dt=2ms에서 수치 발산. I_rot·N²(실물리)로 해결.

남은 실시간 과제: GPU가 샘플은 병렬화하나 순차 스텝 깊이(H×sub=150)가 wall-clock 바닥(~950ms). 실시간(20ms)엔 H·sub 축소가 필요.
