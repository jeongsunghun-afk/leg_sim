# push 실험 계획 — 각도 시험 + 평발 스윕 2변형 (2026-08-25 준비)

세 실험으로 남은 경로(thigh 힘경로 · foot)를 전부 닫는다. **순서대로** — ①이 ②③의
foot 각도 신뢰를 정한다.

⚠ 공통: 로봇 고정 · GUI 는 ②③에서만 끈다(①은 GUI 사용) · 저울 15 kg/5 g ·
기입은 "저울 5초 ±10 g 안정" · 유격은 심으로 저울을 올려 100~300 g 창.

## ① foot(+calf) 각도 시험 — 배율 문제인지 α 문제인지 가른다 (~10분, GUI 사용)

**원리**: 위치서보는 α 와 무관하게 목표각에 도달한다. 명령각 대비 **물리 회전각**이
다르면 그건 순수하게 배율(실효 감속비) 문제다. gear_k 1.5/1.2 는 HW 설계값
(10.5/8.4 ÷7) — 벤치 회귀의 "실효 1.6" 힌트가 실재인지 여기서 갈린다.

```
  ./run_deploy_hw.sh   (1점) · GUI 켜기 · [JOG 검증] 모드
  1. 폰 수평계를 발판(발 링크)에 대고 0° 자세의 각도 기록
  2. jog 슬라이더로 foot +30° → 정착 후 물리 각도 기록 → 0° 복귀
  3. foot −30° → 기록 → 0°
  4. calf 도 동일 (+20/−20° — 정강이에 수평계)
  5. 반대 다리 반복
```

| 축 | 명령 | HL 물리각 | HR 물리각 |
|---|---|---|---|
| foot | +30° | ___ | ___ |
| foot | −30° | ___ | ___ |
| calf | +20° | ___ | ___ |
| calf | −20° | ___ | ___ |

**판정**: 물리각 = 명령각(±2°) → 배율 정상 = 저울에서 보이는 손실은 α 쪽.
물리각 ≈ 명령×1.2/1.6 = 22.5°(foot) → 실효 배율 이상 실재 → 드라이버 설정/기구 조사.
(+/− 평균으로 백래시 소거. 좌우가 다르면 그것대로 중요 정보.)

## ② 평발 · 발바닥 전체 스윕 — thigh 힘경로 = α 해석의 최종 판별 (~15분)

★발바닥 두 점(발끝+뒤꿈치)이 다 닿으면 **발목토크는 압력분배만 바꾸고 총합에 안
실린다** — 그래서 이 변형은 hip 38% · thigh 60% · calf 2% 를 잰다.

```
  배포기 Ctrl+C → ./run_deploy_hw.sh flat    (home = Qflat8 · 재빌드 불요)
  GUI 끄기 → python3 tools/push_scale.py --leg HL --max 30 --step 5
  home 대기 중: 저울을 발바닥 전체가 올라가게 + 심으로 100~300 g 창 → 엔터
  (HR 반복)
```

**예측 — α 해석의 최종 판별이 여기 있다**:
| 기울기 | 뜻 |
|---|---|
| **≈ 0.83** | ★α 공통(0.83) 확정 — thigh 의 g* 0.95 는 모델중력 과대였음(가정 1개 해석 완결) |
| **≈ 0.91** | thigh 구동기만 실제로 강함(축별 α) — 해석 재고 |

## ③ 평발 · 발끝만 스윕 — foot 경로 (~15분)

저울을 **발끝만 올라가게**(뒤꿈치는 저울 모서리 밖) 배치 — 접촉 한 점이 되어
발목토크가 총합에 실린다: hip 24% · thigh 37% · **foot 38%**.

```
  (②와 같은 flat 상태) push_scale --leg HL --max 30 --step 5
  home 대기 중: 저울 위치만 발끝 전용으로 조정 → 엔터
  (HR 반복)
```

**예측**:
| 기울기 | 뜻 |
|---|---|
| ≈ ② 와 같음 (0.83대) | foot 경로 정상 |
| ② 보다 0.05+ 낮음 (~0.75) | foot 경로 ~25% 손실 실재 → 원인은 ①의 각도 결과로 분리 |
