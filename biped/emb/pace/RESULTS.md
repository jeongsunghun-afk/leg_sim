## 0. 무엇을 채웠나 — 수식으로

한 축이 따르는 식은 이것이다. **각 항이 어느 파라미터고, 무엇으로 채웠는지** 표시했다.

```
 τ_cmd(t − T_d)  =  [ I_link + I_rot·N² ]·q̈  +  b·q̇  +  τ_c·sgn(q̇)  +  g(q)
      └── ⑥ ──┘      └─ ① ─┘  └─ ② ─┘         └ ③ ┘    └──── ④ ────┘   └─ ⑤ ─┘
                     └──── dof_armature ────┘   dof_damping  dof_frictionloss

 그리고 발목만:   q_raw = q_foot + coef·q_calf   ← ⑦    (엔코더·명령·토크 전부 이 좌표)
 관측:            q_enc = q_true + q̃_b          ← ⑧
```

| | 항 | 무엇으로 채웠나 | 상태 |
|---|---|---|---|
| ① | `I_link` 링크 관성 | **CAD** — 실측으로 검증 | ✅ calf·foot ±8.3% · thigh·hip 미검증 |
| ② | `I_rot·N²` 로터 반사관성 | **각축 토크시험** ROTOR_I 7.327e-4 | ✅ 4곳 ±10% |
| ③ | `b` 점성 | **일정속도 스윕이 기울기를 직접 준다**(아래 ★) | ✅ calf·foot **0** · ❌ thigh·hip |
| ④ | `τ_c` 쿨롱마찰 | **PACE** (각축과 25% 차) | ⚠ ③과 맞바꿔져 나눔이 안 됨 |
| ⑤ | `g(q)` 중력 | **중력표 + 자세별 실측보정** | ✅ 시험 내부용 (MJCF 는 CAD 가 계산) |
| ⑥ | `T_d` 지연 | **직접 실측** 8.39±0.79 ms | ✅ 좋다 |
| ⑦ | `coef` 커플링 | **경사계 실측** — 무릎 80.5° 훑어 발바닥 절대각 불변 | ✅ **c = 1 확정** (오차 ≲ 4%) |
| ⑧ | `q̃_b` 엔코더 영점 | **PACE** 축별 8개 | ✅ 최대 0.52° |

**⇒ ①②⑥⑦⑧ 은 닫혔다. ③④ 는 총량만 맞고 나눔이 안 됐다.**
③④ 가 갈리려면 **속도를 독립 제어하는 시험**이 필요하다(§5 '재수집' · '일정속도 시험').

⚠MuJoCo 는 이 식 그대로가 아니다. `τ_c·sgn(q̇)` 만 있고 **정지마찰(Stribeck) 항이
없다** — 실측에서 운동마찰이 정지마찰의 72~98% 였는데 그 차이를 표현할 수 없다.
도메인 랜덤화로 덮는 게 현실적이다.

### ★`b` 는 왜 안 잡히나 — **찾으려는 값이 없다** (2026-08-14)

일정속도 스윕은 `q̈ = 0` 이라 관성이 사라진다. 그러면 `f(q̇) = τ_c + b·q̇` 이고
**기울기가 곧 `b`** 다. 저장된 스윕 자료(`results/sweep_ch*.npz`)를 전 축에 대해 풀었다:

| 축 | 속도별 마찰 [Nm] | 기울기 `b` | |
|---|---|---|---|
| **HR_thigh** | 2:0.691 → 60:**0.505** | **−0.160** | ✗ 음수 |
| HL_calf | 2:0.651 → 120:0.597 | −0.028 | ✗ 음수 |
| **HR_calf** | 2:0.701 → 120:0.681 | **−0.0001** | ≈ 0 |
| **HL_foot** | 5:0.650 → 20:0.650 | **−0.001** | ≈ 0 |
| HR_foot | 2:0.653 → 40:0.597 | −0.084 | ✗ 음수 |
| hip | 2:0.88 → 5:0.83 | (−1.01) | ⚠ 점 2개뿐 — 의미 없음 |

**마찰이 속도에 따라 늘지 않고 줄어든다.** Stribeck 이다.

⚠**"그러니 `b` 가 존재하지 않는다" 로 읽으면 안 된다** (2026-08-14 내가 한 번 그렇게
단정했다가 정정한다). Stribeck 곡선은 **내려갔다가 올라간다** — 최저점 아래에서는
마찰이 줄고, 그 **위에서 비로소 점성으로 늘어난다.** 우리가 본 음수 기울기는
"최저점 아래에서 쟀다" 는 뜻이지 "`b` 가 없다" 는 뜻이 아니다.

| 축 | 스윕이 닿은 속도 | 거기서 본 것 |
|---|---|---|
| **calf** (stroke 56°) | **120 dps** | 80·120 에서 **평탄**(0.693/0.681) → 최저점 **위**. `b ≈ 0` 확정 |
| **thigh** (stroke 40°) | 40 dps (60 은 표본 155개로 불량) | 아직 **내리막** → 최저점 **아래** |

⇒ thigh 는 *"찾을 값이 없다"* 가 아니라 **"찾을 수 있는 구간에 못 갔다"** 다.

★그리고 처프는 **반대쪽 반쪽**이다. 새 자료가 thigh 를 114.8 dps 까지 올려 최저점
위로 갔는데, 거기선 관성이 점성의 **28배**라 못 본다.

```
스윕:  관성 없음   · 속도 ≤40 dps  (내리막)   ← 둘 다 반쪽이다
처프:  속도 115 dps · 관성 28배
```

**"고속 + 무관성" 을 thigh 에서 못 만든 것**이 진짜 문제다. calf 은 스트로크가 56° 라
그 조합을 만들 수 있었고, 그래서 답이 나왔다.
⇒ 필요한 것은 **thigh 스윕을 80~120 dps 로** 올리는 것이고, 그러려면 스트로크가
  40° → 56° 쯤 돼야 한다(등속 구간이 남으려면 `stroke/v` 가 정착시간을 넘어야 한다).
  ⚠44° 에서 *"늘어진 다리가 아래쪽에서 간섭"* 전례가 있다 — **육안 확인이 먼저**다.

★**독립적인 두 방법이 같은 말을 한다** — 이게 이 표를 믿는 근거다:

| | 스윕 기울기 | PACE 적합 | |
|---|---|---|---|
| HR_calf | **−0.0001** (≈0) | `JDAMP.calf` → **0**, 5판 산포 **2%** | ✓ 일치 |
| HR_thigh | **−0.160** | `JDAMP.thigh` 0.011~0.180, **8.1배** | ✓ 일치 |

`calf` 가 잘 정해진 건 운이 아니라 기울기가 실제로 0 이기 때문이고, `thigh` 가 안
정해진 건 기울기가 음수라 넣을 값이 없기 때문이다.

⇒ **최저점 위에서 평탄한 게 확인된 축**(calf)은 `dof_damping = 0` 이 정답이다.
  thigh 는 그 확인이 없으니 **0 은 잠정값**이다 — 음이 아닌 값 중 최선이긴 하나,
  80~120 dps 에서 올라갈 가능성이 남아 있다. 그 속도로 걸을 계획이면 확인해야 한다.
  남는 Stribeck 성분은 MuJoCo 로 표현할 수 없으니 도메인 랜덤화로 덮는다.
⚠hip 은 상자가 ±6° 라 속도점을 2개(2·5dps)밖에 못 얻었다 — 기울기 자체를 못 낸다.

## 0-b. 왜 각축이 필요했나 — 다축 PACE 의 세 한계

**출발점은 다축이다.** 8축을 동시에 처프로 흔들어 궤적을 재현하도록 파라미터를 맞춘다
(`collect_multichirp` → `pace_cmaes`). 자연스러운 방법이고, 실제로 대부분을 이걸로 정했다.
그런데 **다축만으로는 원리적으로 못 가르는 것이 셋** 있었고, 각축은 그걸 메우려고 붙였다.

> **먼저 말 두 개.** 다축 최적화(CMA-ES)는 무에서 값을 찾지 않는다.
> **어딘가에서 출발해서**(= **초기값**), **정해둔 범위 안만** 뒤진다
> (= **탐색범위**). 둘 다 각축 실측에서 왔다 — 그게 각축이 다축을 도운 방식이다.
> 탐색범위 끝까지 밀려 멈춘 값은 **찾은 값이 아니라 더 못 간 값**이다(표의 ★).

### 한계 ① 두 값을 맞바꿔도 티가 안 난다 — 궤적으로는 **원리적으로** 못 가른다

`JDAMP.foot` ↔ `JFRIC.foot` 상관 **r = +0.93**. 점성을 올리고 마찰을 내리면 궤적이
거의 같아진다. 그래서 둘의 합만 정해지고 **나눔이 안 된다**(남은 불확실 −66 ~ +64%).

> `design_excitation.py` 가 **설계 단계에서 이미 예측했다.** 궤적 쪽 처방
> (dual·f0scale·f1scale)을 전부 시도했지만 실패했다 — 가진을 어떻게 설계해도 안 갈린다.
> ⇒ **한쪽을 바깥에서 못박는 것 말고는 방법이 없다.**

### 한계 ② 어떤 축은 틀려도 티가 안 난다

비용이 **8축·60창을 통째로 뭉친 단일 RMS** 다(`cost_of`: `sqrt(mean(r²))`).
그래서 자극이 큰 축이 비용을 지배한다:

| | 값 | 결과 |
|---|---|---|
| `JDAMP` 를 틀렸을 때 / `ROTOR_I` 를 틀렸을 때 **RMS 가 변하는 양** | **1/16 ~ 1/87** | 감쇠를 크게 틀려도 RMS 가 거의 안 변한다 |
| **hip 이 비용에서 차지하는 비중** | **4 %** | hip 을 아무 값으로 둬도 통합 RMS 가 안 움직인다 |

⚠**hip 은 자유변수였는데도 초기값에서 안 움직였다.** 금지된 게 아니라 **정보가 없어서**다.
  겉보기엔 "다축이 정한 값" 인데 실제로는 각축값이 그대로 통과한 것이다(§1 의 ⚠ 표시).

### 한계 ③ 자유변수가 **모델오차를 흡수한다**

지연 `T_d` 를 자유롭게 두자 실측 밖으로 달아나면서 다른 값을 끌고 갔다:

| 탐색범위 | 추정 T_d | RMS | ROTOR_I 오차 |
|---|---|---|---|
| 2 ~ 16 ms (자유) | **12.83 ms** ← 실측 8.39±0.79 **밖** | 0.0615 | **−6.7 %** |
| 6.8 ~ 10 ms (실측으로 묶음) | 9.46 ms | **0.0449** (−27%) | **+1.5 %** (4.5배 개선) |

**묶었더니 RMS 도 좋아지고 물리값도 맞았다.** 원문이 `T_d` 를 자유로 두는 건 그걸 따로
재지 않아서다 — **우리는 쟀으니 묶는다.** 실측이 있는 값을 자유로 두면 나머지가 그리로 흐른다.

⇒ 여기서 **"RMS 가 낮다 ≠ 적합이 좋다"** 가 드러난다. 이 교훈은 따로 뺀 구간 검증에서 한 번 더
  반복된다(§5 — 적합에 안 쓴 구간으로 검증해도 네 번 연속 틀린 구조를 골랐다).

### 각축이 준 것 — 그리고 각축도 못 하는 것

각축(`--solo`)은 **한 축만 τ_ff 로 흔들고 나머지를 잡는다.** 다축이 못 가르는 것을
바깥에서 못박는 역할이다.

| 각축이 준 값 | 어떻게 | 다축의 어느 한계를 메웠나 |
|---|---|---|
| **`ROTOR_I` 7.327e-4** | τ_ff 경로(순환 없음). foot 7.327e-4 · calf 공통속도법 7.340e-4 → **0.17% 일치** | ③ 초기값을 참값에 놓음 |
| **foot `damping` 0.110** | 토크시험 q̈ 대 q̇ 크기 직접회귀(HL 0.12 · HR 0.10) | **① 맞바꿈을 밖에서 끊음** |
| 쿨롱마찰(스윕·토크절편) | 저속 평탄부 / 절편 q̇→0 외삽 | ① 탐색범위·초기값 |
| **`T_d` 8.39±0.79 ms** | 왕복지연 직접 실측 | **③ 경계를 좁힘** |

**⚠각축도 만능이 아니다:**

- **`thigh` 관성은 원리적으로 못 잰다.** `--solo` 는 아래 calf+foot 이 매달린 **진자**다
  (주기 0.90 s). 런이 0.21~0.48 s 로 **주기의 39%** 라, `M⁻¹` 예측이 전제하는 t→0 극한이
  깨진다. 자유(0.189)와 고정(0.221) **사이 어디도 아닌 값**이 나온다 → CAD 를 쓴다.
- **중력이 큰 축이 오염된다.** hip \|τ_g\| 5.5 · thigh 6.35 Nm. 보정은 한 점에서 하는데
  시험은 ±53° 를 훑어 잔차가 방향 비대칭으로 남는다. hip 은 τ_trip 에도 걸려 **미측정**이다.
  ⇒ 남은 미해결이 전부 여기로 모인다(§5).

### 그래서 최종값은 **출처가 셋으로 갈린다**

```
  각축 직접측정 (--solo)
        │   초기값(출발점) 과 탐색범위(허용 범위) 를 준다
        ▼
  다축 CMA-ES (9모수)
        │
        ├─ 자극이 있는 축 ──────▶ 다축이 정한 값     thigh · calf · foot
        └─ 자극이 없는 축(hip 4%) ▶ 각축값이 그대로   hip ⚠
        │
        ▼
  fit_v2  (최종)
```

| 고정의 정도 | 대상 | 뜻 |
|---|---|---|
| **완전 고정** | `T_d`(6.8~10 ms) · foot `damping` | 실측이 있으니 흘러가지 못하게 묶음 |
| **초기값 + 탐색범위**(×0.3~3) | `ROTOR_I` · 전 축 `JDAMP`/`JFRIC` | 각축값 중심으로 다축이 그 안에서 정함 |
| **사실상 고정** ⚠ | **hip** `JDAMP`·`JFRIC` | 자유변수인데 자극이 없어 초기값에 머묾 |
| **탐색범위 끝에 붙음** ★ | calf `JDAMP` · foot `JFRIC` | 탐색범위 아래 끝까지 밀렸다 — "찾은 값" 이 아니라 **"더 못 내려간 값"** |

⇒ **§1 의 표는 이 세 갈래의 결과**다. ⚠ 와 ★ 를 그렇게 읽을 것.

0.240/0.241 로 **±0.4%** 일치했다. 정보가 많은 쪽을 쓴다.
⚠나머지는 섞지 않았다 — `thigh`·`calf` 의 마찰은 `damping`=0 과 **짝**이라 같은 판에서 와야 한다.

### ★`JDAMP` 와 `delay` 는 **같은 것을 본다** (2026-08-14)

제어법칙 `τ = kp·(q_cmd(t−T_d) − q) − kd·q̇` 에서 지연을 1차로 펴면:

```
q_cmd(t − T_d) ≈ q_cmd(t) − T_d·q̇_cmd
⇒ τ ≈ kp(q_cmd − q) − kd·q̇  −  kp·T_d·q̇_cmd
       └ 위치항 ┘              └── 새 속도항 ──┘
```

⚠**`kp` 는 하나다.** 새 게인이 생긴 게 아니라, `kp` 가 곱해지는 대상이 `q_cmd` 였고
그 안의 시간지연이 **속도 성분을 뱉어낸** 것이다.

⚠⚠**그리고 동등성은 근사다 — 주파수에 의존한다.** 새 항은 `q̇_cmd`(명령속도)이지
`q̇`(실제속도)가 아니다. `q̇_cmd` 중 **`q̇` 와 위상이 같은 성분만** 감쇠로 작동하고,
직각 성분은 감쇠가 아니라 **유효 강성·관성을 바꾼다.**

동상 비율은 `cos(폐루프 위상지연)` 이다. thigh 로 계산하면:

| | |
|---|---|
| 폐루프 고유진동수 `√(kp/I)` = √(50/0.18) | **2.65 Hz** |
| 처프 끝 `f = 1.25 Hz` → `r = 0.47`, ζ≈0.7 | 위상지연 **≈ 40°** |
| **동상 비율 `cos 40°`** | **0.77** |

즉 `kp·T_d` 의 **약 77% 만** 감쇠로 작동한다. 저주파에서는 1.0 에 가깝고 대역에
가까울수록 줄어든다.

★**이것이 수치 확인이 딱 안 맞은 이유다** — 예측 `Δb = −kp·ΔT_d = −0.0905` 인데
실제는 `−0.0591`(**65%**)이었다. `cos 40° = 0.77` 에 `JFRIC` 이 같이 움직인 몫을
더하면 그 정도다. **동등성을 정확한 등식으로 쓰면 안 된다.**

`T_d = 9.75 ms` 기준으로 축별 크기를 보면 왜 `JDAMP` 가 안 잡히는지 분명하다:

## 5. 끝난 시험 — 결론만

여기 것들은 **다시 할 필요 없다.** 왜 그렇게 결론 났는지만 남긴다 —
이 기록이 오늘만 네 번 헛된 실기를 막았다.

### ✓ `coef` 크기 — **경사계로 c = 1 확정**

> **`c` 가 무엇인가** (2026-08-14 실제로 헷갈린 지점이라 여기 못박는다)
> ```
> q_raw_foot = q_foot + c·q_calf        ⇔        q_foot = q_raw_foot − c·q_calf
> ```
> `q_raw_foot` 은 발목 **모터축**각(엔코더가 읽는 값), `q_foot` 은 발목 **관절각**
> (**정강이 기준**, MJCF 의 joint 값), `q_calf` 는 무릎 관절각이다.
> 발목 모터를 세워두면 `Δq_foot = −c·Δq_calf` 이므로:
>
> **`c` = 무릎이 1° 돌 때 발목 *관절각*이 몇 ° 돌아가는가** (부호 반대). 비율이다.
>
> 무릎 +80.5° · 발목 모터 고정일 때:
>
> | `c` | 발목 **관절각**(정강이 기준) | 발바닥 **절대각**(공간 기준) |
> |---|---|---|
> | **1.0** | **−80.5°** | **0°** ← 자세 유지 |
> | 0.9 | −72.5° | +8° |
> | 0 | 0° (정강이에 붙어 감) | +80.5° |
>
> ⚠*"발이 자세를 유지한다"* 는 **결과이지 정의가 아니다** —
> `발_절대각 = q_calf + q_foot = q_calf·(1−c)` 라서 `c=1` 에서 0 이 되는 것뿐이다.
> 정강이 기준으로는 −80.5° 나 돌아가는데 정강이 자체가 +80.5° 돌아 상쇄된다.
> ⚠`c` 는 **감속비와 무관하다.** 같은 두 축에 원인이 다른 값이 겹쳐 있다 —
> `gear_k`(calf 1.5 · foot 1.2)는 드라이버가 전 축을 7:1 로 착각해 생긴 **배율**이고,
> `c` 는 **링키지 커플링 비율**이다.

`diag/couple_magnitude.py --leg HL` (k=0 영점시험). 발목을 **채널각 고정**으로 잡고
무릎만 손으로 훑은 뒤 발바닥 절대각을 읽었다.

| | 값 |
|---|---|
| 무릎 스윙 | 채널 **120.8°** = 관절 **80.5°** |
| 발목 채널 | 래치 `+2.48°` → 종료 `+2.48°` (**추종오차 ≈ 0**, τ −0.03) |
| **발 링크** 절대각 변화 | **없음** |
| ⇒ | **c = 1** |

`Δ발_절대각 = Δq_calf·(1−c)` 이므로 이 스윙에서 `c` 가 1 이 아니었다면:

| `c` | 예상 Δtilt 크기 |
|---|---|
| 1.00 | 0° |
| 0.95 | **4°** |
| 0.90 | **8°** |
| 0.76 | **19°** |

⇒ 육안으로 3° 를 가른다고 보면 **|1−c| ≲ 0.04**. 경사계 수치를 읽었다면 ±1°/80.5° 로
**≲ 0.012** 까지 좁혀진다.

★**가장 위험한 실패 방식이 배제됐다.** 발목이 밀리면 `Δtilt` 가 줄어 `c` 가 1 쪽으로
**가짜로** 수렴한다 — "c=1 확인" 이 측정 실패에서 나오는 것이다. 그런데 발목 채널이
래치값에 그대로 있었고 토크도 −0.03 이었다. 안 밀렸다.

⚠**2026-08-10 의 "육안 일치" 와는 근거의 무게가 다르다.** 그때는 무릎을 30° 정도만
돌렸을 것으로 보이는데, 그러면 `c=0.9` 여도 3° 라 놓칠 수 있다. 이번은 80.5° 다.

> **접촉 구성 — 용도별로 둘이다** (2026-08-14 사용자 확인)
>
> | 용도 | 접촉 | 비고 |
> |---|---|---|
> | **stand** | **2점** (heel + toe) | MJCF `*_sphere` + `*_sphere2` |
> | **walk** | **1점** (point foot) | 피치 모멘트를 못 내므로 발목 토크로만 자세를 잡는다 |
>
> ⚠어긋난 게 아니라 **의도된 두 구성**이다. MJCF 머리말의 "평발" 은 stand 구성을 말한다.
>
> ★**식별에는 무관하다.** `pace_cmaes` 롤아웃은 **base 고정 · 바닥 제거**라 접촉이
> 0 개다(`d.ncon == 0`). 접촉구는 질량도 없다(URDF inertial 이 질량을 정한다).
> 질량·관성은 두 구성이 같으므로 `armature`·`frictionloss`·CAD 검증(발 −8.3%)이
> 그대로 유효하다.
> ⚠단 **경사계를 댈 평면은 stand/walk 와 무관하게 발 링크의 가공면**이다 —
> 발바닥 평면이 있다고 가정하면 안 된다.

⇒ **저장소의 마지막 미측정 구조 파라미터가 닫혔다.** `couple_coef: 1.0` (config) 과
MJCF tendon `coef="1"` 을 그대로 둔다. PACE 도 `--pin coef` 로 계속 고정한다.

<details><summary>남은 것 — `--k 1.0` 눈금 판 (선택)</summary>

그게 맞으면 경사계·스윙각·미끄러짐까지 **계측계 전체**가 검증된다.

### ✓ 중력 최소자세 — **전제가 틀렸다**

크다"* 고 적고, 시험 자세를 중력 최소로 옮기자고 했다. **계산해 보니 틀렸다.**

|---|---|---|
| `thigh` 관성 | 중력이 크다 | ✗ **중력은 이미 해결됐다** — §2 가 *"중력창으로 방향편차를 15.8%→2.6% 로 잡았는데도 +31% 가 남는다"* 고 같은 문서에서 적고 있다. 원인은 **진자 뒤처짐** |
| `hip` 감쇠 | 중력이 크다 | ✗ **중력은 상수 5.25 Nm** 이라 `(τ⁺−τ⁻)/2` 에서 상쇄된다. 원인은 **±6° 상자** |
| `calf` 감쇠 | 중력이 크다 | ✓ 해결됨 — `JDAMP.calf = 0` (§0 ★) |

그리고 **자세로는 못 줄인다.** MJCF 로 계산한 값:

| | 결과 |
|---|---|
| `hip` τ_g | thigh·calf 를 어떻게 접어도 **5.25 Nm 불변** — 롤축이라 옆방향 모멘트팔이 안 변한다 |
| `thigh` τ_g (스트로크 ±15°) | 변화폭이 calf 자세와 무관하게 **1.5~1.7 Nm** (calf 40° 로 해도 10% 개선뿐) |

#### 그래서 진짜 레버는 축마다 다르다

**`thigh` 관성 — 런을 짧게.** 진자 주기 0.90 s 대비 런이 0.21~0.48 s(39%)라 `M⁻¹`
예측이 전제하는 `t→0` 극한이 깨진다. 중력최소 자세(thigh +20°·calf +20°)에서 τ_g 가
0.023 Nm 이고 `τ_trip` 12 Nm 이라 **예산이 11.7 Nm** 남는다. 유효관성 0.139 이므로
`q̈` 를 **84 rad/s²** 까지 쓸 수 있고, 그러면 `vref` 100 dps 도달 + 창(±50 ms)까지
**~70 ms** 로 끝난다 — 주기의 **8%**. 지금은 그 예산을 다 안 쓴다.
⇒ 고칠 것은 **자세가 아니라 토크준위**다(`auto_levels`).

**`hip` 감쇠 — 방법이 없다.** 상자 ±6° 는 **자기충돌**이 정한 것이다(지그 접촉 11.5°,
처짐 2~3.5° 를 빼면 6° 가 상한). 등속 스윕은 `stroke/v > 정착시간` 이라 **47 dps** 가
한계이고 거기서 점성 몫이 11% 다. 속도점도 2개(2·5dps)뿐이라 기울기를 못 낸다.
⇒ **도메인 랜덤화 대상으로 확정한다.** 더 팔 데가 없다.

★교훈 — §5 '일정속도 시험' 과 **같은 실수**를 반복할 뻔했다. "중력이 원인" 이라는 진단이

### ✓ `coef` PACE 식별 — **해봤다. 이 데이터로는 안 된다**

`coef` 를 탐색변수로 넣었다(`pace_cmaes.py`, `set_coupling_coef` + `retarget_coupling`).
`q_raw` 는 coef 가정과 무관하게 정확하므로 `q_foot_true = q_raw − c·q_calf` 로 다시 풀어
비교한다. `c=1` 이 항등이라는 것부터 확인했다 — 기존 결과가 소수 4자리까지 재현됐다.

**결과: `c` 를 자유로 풀면 오히려 나빠진다.**

| | 적합 | 따로 뺀 구간 | `coef` |
|---|---|---|---|
| `fit_v2` — `coef` 고정 1.000 | **0.4050** | **0.3967** | 1.000 |
| `fit_v3` — `coef` 자유 | 0.4058 | 0.3983 | 1.064 |

차원만 하나 늘고 얻은 게 없다. **데이터는 `c = 1.0` 을 반박하지 않는다** —
그대로 두면 된다. (탐색범위 0.70~1.15 는 코드에 남겨 뒀다. 기본은 `--pin coef` 고정.)

> ★**중간에 오판이 있었다 — 이 교훈이 결과보다 중요하다.**
> `x0` 에서 `c` 를 1-D 로 훑었더니 최소가 0.76 이었고, 따로 뺀 구간도 −7.6% 로 따라왔다.
> `JDAMP.calf` 와 맞바꿈인지 격자로 확인했더니 **네 행 전부 최소가 `×0.5`** 였고,
> 그걸 *"coef 와 무관하다 = 독립이다"* 로 읽어 "맞바꿈 아님, 결정적" 이라고 보고했다.
> **틀렸다.** `×0.5` 는 훑은 범위의 **끝**이었다. 진짜 최적은 `JDAMP.calf = 0.0097`
> (`×0.108`)로 격자 밖이었고, 거기까지 열어 주면 calf 잔차가 그쪽으로 흡수되어
> `coef` 는 할 일이 없어진다.
> ⇒ *"탐색범위 벽에 박힌 값은 식별된 값이 아니다"* 는 **격자 훑기에도 똑같이 적용된다.**
> `tests/scan_coef_jdamp.py` 에 행 최소가 격자 경계면 판정을 보류하는 가드를 넣었다.

`coef` 크기를 정말 재려면 **엔코더 밖**으로 나가야 한다 — §5 '`coef` 크기' 참조(경사계로 끝났다).
