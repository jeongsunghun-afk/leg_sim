2점 stand 는 섰지만 떨리고 기운다 — 원인 넷을 데이터로 갈랐다

이번 세션에서 2점 평발 stand 가 처음으로 체중을 받았다. 그러나 심하게 떨리고 시간이 갈수록 한 방향으로 기운다. 두 현상은 원인이 서로 다르며, 기움은 원인이 확정됐고 떨림은 후보를 여섯 개 배제해 하나로 좁혔다. 통신 동결은 5건을 포렌식으로 확보했다.

01기움 — 원인 확정

확정IMU 가 죽어 있어 자세 오차를 아예 못 본다

WBIC 의 자세 레벨링 태스크는 base 쿼터니언으로 기울기 오차를 계산하는데, 그 값은 IMU 에서 온다. 현재 IMU 는 전 채널 0 이라 쿼터니언이 항상 단위(=완전 수평) 다. 따라서

oerr ≡ 0  →  레벨링 목표 가속도 = 0  →  아무리 기울어도 보정 명령이 안 나간다

실측: CoM 오차가 2.5 cm → 5.9 cm 로 단조 증가(밑창 반길이 7.3 cm 의 80%), 육안으로도 실제 기울기 확인. 이건 튜닝으로 못 고치며 IMU 복구가 stand·walk 의 전제다.

복구안은 이미 진단이 끝나 있다(emb/IMU_RECOVERY.md): halIMU.cpp:164-167 이 파싱 결과를 [0] 행에 쓰는데 게터는 Body = 4행을 읽는다 → Body 슬롯 영구 0. 수정은 [0] → [unDevID] 4곳이고, MCU 펌웨어가 아니라 Pi 앱 재컴파일로 끝난다.

남은 설명은 하나다. WBIC 는 조작된 base 자세(IMU 0 → 항상 수평)로 지면반력을 계산하므로, 권한이 커질수록 모델 오차가 그대로 커진다. 여기에 HL_calf 유격 7° (토크가 유격 안에서 헛돌다 충돌)가 겹치면 8 Hz 대 성장과 부합한다.

⇒ IMU 복구 전에는 stand 튜닝이 무의미하다. 가짜 자세를 먹는 제어기를 튜닝하는 셈이다.

  3. 드라이버 폴트 비트를 처음 확보 — 상태워드 0xC0(bit6+bit7)이 ch2·ch3·ch4 에서 2건. 그동안 “전부 00”만 보던 것이다. 비트 정의를 RGA 에 확인해야 한다.
  4. rx_crc·rx_err 전 사건 0 ⇒ 이더넷 전기 노이즈는 아니다. Emb 프로세스는 항상 살아 있었다.

04고친 것

수정QP 등식 rank 축퇴 — 실재 버그

2점 평발 stand 에서 QP 실패율 20~33%(접지 불량 시 75%), 사유코드 4 = REDUNDANT_EQUALITIES. 원인은 수치가 아니라 구조다 — 한 발에 접촉점이 둘인데 발은 강체라, 두 점의 가속도 구속 6행 중 선 방향 1행이 종속이다. 발이 둘이니 정확히 2행(실측 rank 16/18). 실패하면 중력보상 폴백으로 떨어지므로 두 해가 번갈아 나간다. rank-revealing QR 프루닝으로 sim 실패 18.5% → 0.0%.

되돌림그 수정을 기본값으로 넣은 것은 잘못이었다

sim 근거만으로 배포기 기본값을 ON 으로 바꿨는데, 실기에서는 균형이 오히려 나빠졌다. 기본 OFF 로 환원했고 WBIC_EQ_PRUNE=1 로만 켜진다. 종전 동작(실패 시 중력보상 폴백)이 최소한 안전측이다. 실기 미검증 상태로 기본값을 바꾸지 않는다를 규칙으로 남긴다.
