02_Leg 14-DOF · quad/simple_mpc/ · aligator OCP (연구용 B·C)

B · C 제어 파이프라인 & OCP 문제 정의

B (Centroidal) = Kinodynamics OCP가 접촉력+관절가속을 계획 → TSID 전신 QP가 토크로 변환. C (FullDynamics) = 전신 강체 OCP가 관절토크를 직접 출력 → Riccati 피드백. 둘 다 aligator SolverProxDDP RTI(max_iters=1).

⚠️ 연구·비실시간 브랜치. OCP solve가 무거워 실시간 GUI 조종은 A(MPC+WBIC, 1 kHz) 전용. B·C는 헤드리스 정량검증·뷰어 관찰용(B~0.2 m/s·C~0.27 m/s marginal). 배포 파이프라인은 pipeline.html(A) 참조.

1 · 공통 골격 02_Leg 14-DOF (nu=nv−6, 앞발목 고정) · URDF _9 · free-flyer · 4 point-feet

두 컨트롤러 모두 2-레이트 구조다. 무거운 OCP를 풀어 계획을 만들고(mpc.iterate(x)), 그 계획을 1 kHz 내부 루프에서 보간(Interpolator)해 매 스텝 저수준 명령으로 실현한다. 상태 x=[q;v] (MultibodyPhaseSpace, dim nq+nv), 호라이즌 T=50 노드, dt=0.01, trot(더블서포트+대각스윙). 발배치·속도 기준은 MPC::updateStepTrackerReferences(Raibert + capture-point)에서 생성, 매 사이클 receding-warm-start.

* 재계산 속도 주의: dt_mpc=0.01은 OCP 노드 간격(계획 해상도 100 Hz)일 뿐, mpc.iterate 실제 solve 벽시계는 ~40 ms → 재계산 ~20–30 Hz(비실시간). 1 kHz 내부 루프는 그 사이 stale 계획을 보간·전개해 메운다(MPC_DECIM). 이 solve 병목이 B·C를 배포에서 제외한 이유(고속보행 한계=언어 아닌 OCP 수렴).

B · OCP 2 · Kinodynamics OCP — 문제 정의

중심동역학(centroidal momentum) + 전신 기구학 결합. 결정변수에 접촉력이 포함되며 토크는 없다(뒤 TSID가 담당). ODE=KinodynamicsFwdDynamics, semi-implicit Euler.

상태 & 결정변수

x = [ q (nq) ; v (nv) ]  base SE3(7)+14관절, base twist(6)+14관절속
u = [ f0..3 (4×3 접촉력) , q¨ (nv−6=14 관절가속) ]  u0=[fref×4, 0], fref,z=mg/nk

control힘·가속 정규화force=0.01 · accel=1e−5

종단(terminal) = state + centroidal×10.

제약

  • 기구학 한계 (box): 관절 [6:nv] ∈ [qmin,qmax]
  • 접촉(stance) (등식): 발 속도 = 0  FrameVelocityResidual{0,1,2} EqualityConstraint
  • 마찰추: force_cone 기본 OFF · 착지 land_cstr 기본 OFF  (μ=0.8, 필요시 env로 ON)

솔버: aligator SolverProxDDP · TOL=1e−4 · μinit=1e−8 · max_iters=1 (RTI) · 8 threads · T=50(Tds=10,Tss=30) · apex=0.15. 출력: forces+q¨ 궤적 → TSID로.

B · ID 3 · TSID 전신 역동역학 — 힘·가속 → 토크

OCP가 낸 계획(자세 q·v·a, 발별 목표 접촉력)을 1 kHz에서 계층 QP(TSID, proxqp)로 실현해 관절토크를 뽑는다. kino_ID.setTarget(...) → tau = kino_ID.solve(t, q, v).

즉 B = Kinodynamics OCP(100 Hz, 힘+가속 계획) → TSID QP(1 kHz, → 토크) 2단 캐스케이드. 토크한계는 OCP가 아니라 이 TSID actuation-bound task가 강제.

C · OCP 4 · FullDynamics OCP — 문제 정의

전신 강체(articulated) 동역학 + 발 강체접촉 제약. 결정변수가 관절토크 그 자체라 별도 ID 단계가 없다. ODE=MultibodyConstraintFwdDynamics(pinocchio prox 접촉), semi-implicit Euler.

상태 & 결정변수

x = [ q (nq) ; v (nv) ]  B와 동일 구조
u = τ (nv−6 = 14 관절토크)  액추에이션 행렬=단위, u0=0. 접촉력은 제약 Lagrange 승수로 내부 복원

솔버: aligator SolverProxDDP · TOL=1e−4 · μinit=1e−8 · max_iters=1 (RTI) · 8 threads · T=50(Tds=8,Tss=20) · apex=0.15. 적용: τ = uinterp − RIC·Ks·(xmeas⊖xinterp) (RIC=1.0), LowCmd kp=kd=0 → τ=tau. 비동기 모드: MPC를 별도 프로세스서 돌려 shared-memory로 1 kHz 실시간 실험.

D1·OCS2 6 · D1(NavBotHub) 대조 legged_control = OCS2 NMPC + 계층 WBC (qiayuanl 계열)

D1은 OCS2 기반 kino-dynamic NMPC(100 Hz) → 계층 WBC(1 kHz)로 추종한다. MPC 모델은 B와 같은 kino-dynamic인데, 2-layer 분리 + HPIPM/single-SQP로 실시간을 달성한다 — 이것이 B·C(단일 OCP, aligator, 비실시간)와의 결정적 차이다. 즉 OCS2 ≈ "B의 모델을 우리 A식 2-layer로 실시간화한 것"이고, 구조상 우리 A(reduced-MPC+WBIC)와 같은 계열이다.

OCS2 솔버가 MuJoCo에 적합한가? 솔버(SLQ/SQP/HPIPM)는 모델-불가지라 알고리즘적으론 문제없다. 관건은 모델이다 — OCS2는 Pinocchio 해석 강체동역학을 NMPC·WBC 양쪽에 쓰고 Gazebo로 시뮬한다. 이를 MuJoCo에 얹으면 Pinocchio↔MuJoCo 접촉/동역학 불일치(sim2sim 갭)가 생기는데, 이건 우리 B·C가 이미 안고 있는 것과 동종 (B/C도 Pinocchio OCP → MuJoCo pt 시뮬). 피드백+튜닝으로 관리되나 "MuJoCo-native"는 아니다. 대조로 우리 A는 WBIC가 MuJoCo의 M·h·J를 직접 읽어 갭이 최소이고, C-2(mjx_ilqr)는 MJX로 MuJoCo를 직접 미분해 sim2sim 갭 0 — MuJoCo-native 그래디언트가 필요하면 이쪽이 정답. 요약: OCS2 솔버는 적합하나, Pinocchio 모델의 sim2sim 갭은 B/C와 동일 수준이다.
