모델기반 험지(갭) 크로싱 탐색 리포트

02_Leg 17-DOF 사족 · 지형계획(TO) 트랙 · 2026-07-27 세션 종합
관련: TOWR_모델기반지형_리포트.md · 제어기_비교.html(A·B·C·D1 지형플래너 계보) · 메모리 b-elevation-tamols-towr-track
한 줄 결론(갱신 2026-07-28) — 계획(TAMOLS)은 OK, 실행(추종기)이 벽. ★C++ TAMOLS 솔버는 완성: 정식화(제약5+비용3)·SQP-RTI를 Drake와 정합 검증, 해석Jacobian으로 <20ms 실시간, Drake seed 없이 self-contained cold-start 수렴(elastic-mode globalization). 그러나 폐루프 크로싱은 실패 — A의 추종기(WBIC+SRBD MPC) 위에서 접근은 falls=0로 잘 추종하나 실제 갭 크로싱서 계획의 1.7× 폭주→CoM이 앞발 넘어 전방tip 낙상. 병목=추종기(A의 SRBD MPC=속도만 추종하는 정상상태 조절기, 공격적 일회성 크로싱을 execute 못함), 계획 아님. 대칭/yaw홀드/느린재생 등 여러 변형 전부 다른방식 실패. 결론: 모델기반 추종기로 robust 크로싱 불가 재확인 → TAMOLS + RL 추종(DTC 정석)이 남은 길.

1목표와 배경

가정환경 험지(문턱·가구밑 갭)의 핵심 난제 = 불연속 지형(갭)에서 base와 발판을 협조시켜 건너기. A(SRBD-MPC+WBIC)·B(kinodynamic MPC)는 폐루프 보행은 되나 발판만 greedy nudge라 갭 협조가 없음. 모델기반 지형계획기(TO) 계보 — TOWR(Winkler)·TAMOLS(Jenelten)·Perceptive NMPC(Grandia) — 중 TAMOLS(base+발판+타이밍 공동최적화, 지형특징 활용)를 정공법으로 검증.

최소 horizon(2-phase)조차 2.6 Hz(cold) — 실시간과 19×, warm-start로도 ~4–13 Hz로 50 Hz 미달. Drake(ianpedroza)는 연구·오프라인용이라 per-solve 오버헤드가 큼. 진짜 TAMOLS 실시간은 전용 C++ fast solver(커스텀 QP, Drake 범용 NLP 아님) 덕이며, 실시간화 = 튜닝이 아니라 C++ 재구현(583× 못 메움).

5★C++ TAMOLS 구현 — 솔버는 완성, 폐루프 크로싱은 추종기서 실패

section 4가 지목한 "C++ 전용 솔버 재구현"을 완수(quad/cpp/tamols/, Drake 단계별 정합 검증). 솔버는 완성됐으나, 그 계획을 A의 추종기로 실행하니 크로싱서 낙상 — 실행층(추종기)이 벽으로 남음.

왜 크로싱서 낙상하나(2026-07-28 진단) — 접근 구간(t=0~1.25s)은 깨끗이 추종(yaw~0°·tilt<15°·falls=0) = base 자세 타이트닝(rp_max 0.20→0.06)이 여기선 작동. 그러나 크로싱(t=1.25~1.75)서 로봇이 계획을 오버슛: 로봇 x=1.037인데 계획 종단 0.724(0.3m 초과, 계획의 1.7× 속도로 폭주). 앞발이 0.69~0.84로 원거리 착지→몸통 급전진 당김→CoM이 앞 스탠스발 넘어 전방tip→yaw 스핀 19→80°→낙상. 근본 원인 = 추종기: A의 SRBD MPC는 x,y 위치를 추종 안 함(Qdiag px=py=0), 속도만 추종하는 정상상태 조절기라, 크로싱의 감속 GRF를 2발 대각지지서 못 만듦. 시도한 변형(yaw홀드 W_YAW·1.6× 느린재생·발판/base 대칭 solve) 전부 다른방식 실패.
  • 솔버(계획)는 성과 — 실시간화(<20ms)·self-contained cold-start·Drake 정합. TAMOLS 계획 품질은 문제없음.
  • 실행(추종)이 벽 — 모델기반 추종기(A-WBIC·B-TSID·자작WBIC·selectFoot)를 바꿔가며 다 시도했으나 험지 크로싱서 공통 실패. 이전 "falls=0 달성" 보고는 marginal·재현 불가였음을 정정.
  • 남은 길 = TO + RL 추종(DTC 정석) — 유일하게 안 해본 추종기. 계획(TAMOLS/TOWR)은 재사용, 추종기만 RL로. [[perceptive-nav-tamols]] RL 피벗과 정합.
결정(정정 2026-07-28) — (a) C++ TAMOLS 솔버 완성(실시간+cold-start). (b) 폐루프 크로싱은 A 추종기서 실패=병목이 추종기임을 확인. 다음 = TAMOLS/TOWR + RL 추종기(DTC). 모델기반 추종기 재튜닝은 헤드룸 낮음(정상상태 조절기 한계).
