02_Leg · 17-DOF · 모델기반 제2트랙

Contact-Implicit MPC 파이프라인

험지(gap·stepping) 크로싱의 근본 한계인 고정 접촉 스케줄을 넘기 위해, 접촉 모드·발판·타이밍을 온라인으로 동시에 발견하는 CI-MPC를 설계·구현한다. 배포 컨트롤러(A: WBIC+MPC)는 불변이며, 이는 병렬 연구 트랙이다.

스택 Crocoddyl · Pinocchio · MuJoCo/MJX(GPU)  ·  코드 simulation/quad/ci_mpc/  ·  참조 Kim et al. 2023, Contact-Implicit MPC (KAIST HOUND)

01 왜 필요한가 — 고정 스케줄의 벽

타이밍을 결정변수로 못 올리면 지형 간격에 스텝을 맞출 수 없다

현재 컨트롤러 A(WBIC+SRBD MPC)·B(centroidal)·C(fulldynamics)는 모두 접촉 스케줄 (T_ds/T_ss)을 고정 입력으로 두는 fixed-schedule이다. 발 cadence·step length가 지형 간격과 우연히 맞는 gap만 넘는다 — 속도-공명(speed resonance). selectFoot(③)은 발판 위치만 nudge할 뿐 타이밍은 못 바꾼다.

타이밍을 최적화하려면 접촉 on/off가 결정변수가 되어야 하는데, 그러면 문제가 비볼록(이산/상보성)이 되어 실시간 볼록 QP가 깨진다. 이 벽을 넘는 두 갈래 = 모델기반 CI-MPC 또는 RL. 지형 이산 발판 탐색은 RL 피벗을 유지하고, 본 트랙은 접촉 모드 창발을 담당한다.

07 걷게 만든 핵심 발견

stance 유지

KP=300 + IK 높이 0.42

PD는 base 중력 피드포워드가 없어 sag한다. IK를 목표+sag만큼 높게 잡고 KP를 올려 stance 유지(KP≥600은 진동).

전진 추진

전진 트롯 gait-prior

스탠스 발을 몸기준 뒤로 sweep(추진)·스윙 발 앞착지. "제자리" prior는 뒤로 표류한다. 물리가 실제 접촉을 결정.

cost 형상

height 추종 제거

높이 추종항은 보행의 자연 bobbing을 벌해 MPPI를 얼린다. 붕괴 barrier + 전진 우세만 두니 크라우치 없이 전진.

미해결 긴장

fast ↔ stable

vx 가중↑ → 크라우치-다이빙 착취(z0.18 낙상). prior가 ~0.12만 안정 지원. 완전 속도엔 긴 스텝 prior + 정교한 shaping 필요.

08 GPU 인프라 (MJX)

CPU 순차 롤아웃(740ms/스텝)은 튜닝 비현실적 → GPU 병렬화

  • RTX 4060 + jax[cuda12] + mujoco-mjx 3.9.0 (proxddp env).
  • ★ 메쉬 충돌 스트립이 결정적 — 몸통 메쉬 충돌을 끄고 발 sphere + 바닥만 충돌시키면 MJX forward JIT 컴파일이 256초 → 8초. (strip_mesh_collision)
  • 전체 롤아웃을 단일 JIT(lax.scan H×sub) + vmap(Nsamp)로 묶어 GPU 병렬.
  • 반사관성(armature)이 폐루프 안정의 전제 — MJCF의 dof_armature=0이면 stiff PD가 dt=2ms에서 수치 발산. I_rot·N²(실물리)로 해결.

남은 실시간 과제: GPU가 샘플은 병렬화하나 순차 스텝 깊이(H×sub=150)가 wall-clock 바닥(~950ms). 실시간(20ms)엔 H·sub 축소가 필요.

13 C-1 로드맵 — HOUND식 해석 그래디언트 실시간 CI-MPC

동기: 참조 레버(BRAKE·STIFF)로도 post-crossing settle(WHEN)·발판(WHERE) 동시해결 불가=marginal(§12). 착지 안정화=접촉 타이밍을 최적화가 직접 정해야 → C-1. 왜 C-2 아닌 C-1: C-2 jacfwd=offline(아래 판정). HOUND 70μs/40Hz는 자동미분 안 씀=해석 도함수.

핵심(novel) = 접촉임펄스 동역학 + 해석 그래디언트: forward=하드접촉 임펄스(속도공간 Signorini LCP+Coulomb, Hwangbo block Gauss-Seidel)+semi-implicit Euler · backward=완화 상보성 해석 그래디언트 ∂λ/∂(q,q̇,u) 닫힌형식(식11-19,26) + Pinocchio ABA 미분. ★C1.2의 하드접촉 해석미분이 관문(참조코드 없음, FD 대조가 안전망). 단 Pinocchio computeConstraintDynamicsDerivatives 내장이 이걸 대폭 de-risk(§12).

남은 C1.2 설계(완화 상보성 레이어) — 3안 조사: Pinocchio setCompliance(순응)·Baumgarte는 있으나 bilateral(발이 떠도 당김)이라 contact-implicit 직접 불가. (A) 완화 상보성(HOUND): λ≥0·gap≥0·λ·gap=ρ 임펄스 솔버(ρ 완화=스무스). (B) gap-의존 compliance: gap>0이면 순응↑(힘~0)·gap<0이면 stiff(단방향 근사). (C) 스무스 active-set: gap 문턱 σ(−gap/ε) 가중. 셋 다 내장 dλ/dq 미분 위에 얹음(per-mode 동역학·그래디언트는 이미 정확). → C1.1(FD sanity)에서 (A)~(C) 중 선택 프로토타이핑.

! C-2 실시간성 판정 — 완성해도 실시간 불가, offline 검증/교사 도구

근본 이유(산수): 병목=jacfwd(forward-mode AD)로 접촉 물리 통과. 선형화 1회 = fx[47×47]+fu[47×17] → 64 JVP 방향 각각 full mjx.step(서브스텝 10 × 순차 접촉솔버). 제어 1스텝 = 64 × 10 × Nh(12) × ITERS(3) ≈ 2~5만 mjx.step. mjx.step 하나 ~10-100μs → ~1-2.5s/iter(실측 일치). 20ms 도달하려면 mjx.step < 1μs = 물리적 불가. GPU 18W/지연-바운드 → 서버 GPU도 무의미. Nh·sub·ITERS 다 줄여도 ~8배(0.5-1s)가 한계 + 품질 저하.

실시간 CI-MPC 자체는 가능 — 다른 구현: HOUND 70μs/40Hz는 자동미분을 안 씀 = Pinocchio 해석 도함수(RNEA/ABA 미분, O(n) 1패스) + 하드접촉 임펄스 해석적 완화-상보성 그래디언트(닫힌 형식, 솔버 미분관통 안 함) + C++. 즉 실시간 = "C-2 더 개발"이 아니라 C-1(HOUND식 해석 그래디언트 C++) 재작성.

C-2의 역할(배포 아님): ① 개념 검증·프로토타이핑(offline) — CI가 fixed-schedule 벽 넘는지 증명·cost 튜닝·거동 규명 (완료: GRF-bounce 벽 돌파·gap1 통과 marginal·STIFF로 개선, §12) ② sim2sim 갭 0(MJX=MuJoCo, C++ 해석판 투자 전 확인) ③ distillation 교사(느리지만 정확 → 빠른 정책 증류, MPC-교사 하이브리드). 배포 두 갈래: (a) C-1 해석 C++(대규모 재작성) (b) C-2 → RL 증류.
