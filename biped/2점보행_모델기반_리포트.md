# biped 2점(평발) 보행 — 모델기반 접근 최종 리포트

**작성 2026-07-21 · 갱신 2026-07-22 · 대상**: biped(quad 뒷다리 유래 8-DOF, 평발) 2점 접촉 보행

**한줄 결론**: 단일지지 pitch 불안정을 완전 규명하고 온라인 centroidal MPC+WBC(D1)·발 형상 개선·발 x오프셋(stagger)·ZMP/DCM 워커까지 모두 시도. **모든 모델기반 접근이 "서기"는 안정화하나 "보행(단일지지 스텝)"은 근본 불가**로 수렴. → **배포 = 1점(점발) 보행 / 2점(평발·박스) 서기 역할분담 유지. 강건 2점 보행 = RL(추후 소스 공급).**

---

## 0. 최종 배포 결정 (2026-07-22)

| 접촉 | 역할 | 상태 |
|---|---|---|
| **1점(점발)** | **보행(walk)** | ✅ falls=0 (발목토크0 → 동적보행) |
| **2점(평발/박스)** | **서기(stand)** | ✅ falls=0 (밑창 ZMP → 정적안정) |

**물리적 역할분담이 정답.** 2점 동적보행은 모델기반으로 불가함을 세션 전체에서 철저히 검증(§2~6). 강건 2점 보행은 RL 트랙으로 이관.

## 1. 목표와 배경

- **목표**: 평발(heel+toe 2점 접촉) biped의 동적 보행.
- **기존 상태**: 배포 데모 = 1점(점발) 보행 falls=0 · 2점(평발) 서기 falls=0.
- **동기**: 평발로도 걷게 하고 싶음.

## 2. 원인 규명 — 단일지지 backward pitch

### 2.1 접촉으로 원인 격리
같은 `biped_flatfoot.mjcf`에서 1점(발목 세운 tip)=전진 falls=0, 2점(heel+toe)=뒤로 pitch 토플. → 모델·질량·스윙 반작용 전부 아님. **순수 평발 단일지지 pitch** 문제.

### 2.2 물리적 원인 (형상)
- **양발이 같은 x**(quad 뒷다리 유래) → 양발지지도 전후 지지폭 = 발 1개(16cm)뿐. **pitch 안식처(전후 지지 폴리곤)가 없음**.
- 발목 **pitch만**(roll 없음) + 발이 **선(heel+toe, 폭 0)** → 단일지지 CoP 권한 협소.
- **발목이 발 뒤끝(heel)에 위치** → backward pitch일 때 CoP를 발목 뒤로 못 보냄(뒤 CoP 마진 ≈ 0).
- 무거운 다리(원래 78%) → 발 드는 순간 큰 각운동량 외란.

### 2.3 정직한 계측 (착시 정정)
- **max-발클리어런스 지표는 주기 stepping과 낙상 flail을 구분 못함** → 초기 "37~103mm 실제 stepping" 보고는 전부 낙상 순간 다리 flail이었음.
- 발 높이 **시계열**(FOOTCSV) + HL-HR 차동 계측으로 확정: **로봇은 한 번도 차동(한 발 위·한 발 아래) 단일지지 스텝을 실행하지 않음.** 서 있다가 텀블.

## 3. 시도한 모델기반 접근 (전부 STANDING만 개선)

| 접근 | Standing | Walking(단일지지 스텝) |
|---|---|---|
| 순간 WBIC · crocoddyl closed-loop · A CoP MPC | ✅ | ❌ |
| crocoddyl **open-loop** (조율된 궤적) | — | ✅(유일, 반응성 없음=배포불가) |
| **D1 online centroidal MPC+WBC** | ✅ base_z0.45·pitch<2°·56Hz | ❌ 스텝 회피 |
| **base pitch-rate 댐핑**(WBV_PITCH) | ✅ 개선 | ❌ |
| **발 형상**(박스 26cm·heel 뒤 12cm) | ✅ 3.5→8s | ❌ |
| **발 x 오프셋**(stagger, 전후 지지폭 20cm) | ✅ 24s | ❌ |
| **ZMP/DCM 워커** | 플래너 ✅ | ❌ 실행=WBC 필요 |

### 3.1 D1 컨트롤러 (`biped/d1/biped_centroidal.py`)
- base=quad_centroidal_17dof.py. simple-mpc(pixi env py3.14). addQuadFoot(평발 6D wrench CoP)·KinodynamicsOCP·MPC 게이트·KinodynamicsID(WBC).
- **서기 성공**(pitch<2°, 실시간 56Hz). **보행 실패**: OCP가 HL swing을 계획(참조 apex 76mm 생성 확인)하나, **계획의 실행 knot(k0)는 항상 평평**·리프트는 먼 horizon에만 → 스윙이 실행 지점에 도달하면 즉시 backward pitch 토플. **발 드는 순간 = 즉 텀블(0.15s).**
- pitch-rate 댐핑(WBV_PITCH 10→500)이 유일하게 유효했으나 **서기 안정**에만(스텝 별개).

### 3.2 발 형상 실험 (`biped_boxfoot.mjcf`, env BOXFOOT)
- 선(16×0cm) → 박스(26×9cm) + heel 발목 뒤 12cm. 스탠스 coplanar 검증.
- **Standing pitch 안정 개선**(발목 뒤 CoP 마진 실제 기여, 3.5→8s). **Walking 여전히 0 스텝.** 33cm 큰 발로도 한 걸음 불가.
- 반증: W_FRAME(발추종) 40배·다리질량 5%(거의 무질량)로도 차동 스텝 안 됨. **블로커 = morphology 아님, 컨트롤러의 단일지지 실행 불가.**

### 3.3 발 x 오프셋 (env STAGGER)
- HL 발 앞·HR 발 뒤 IK로 양발 다른 x = 전후 지지폭 20cm. **STAND는 24s+ 안정**(안식처 확보). **gait ON시 스텝 여전히 0**, 텀블.

### 3.4 ZMP/DCM 워커 (`biped/zmp/biped_zmp.py`)
- 자립형 DCM(Divergent Component of Motion) LIPM 워커. **플래너 정상**(footstep+DCM 역recursion+CoM 적분+swing Bezier, IK 발오차 0mm).
- **실행 근본 실패**: 부유 base를 순수 IK+PD/위치서보로 못 구동(commanded/measured-base·중력보상·위치서보 전부 폭발, 200ms). **부유 base biped = whole-body 역동역학 필수.** + 이 로봇 standing 자체가 marginal.

## 4. 근본 결론

**이 biped 형상(quad 뒷다리·양발 同x·발목 pitch만·무거운 다리·marginal standing)은 모델기반 단일지지 walking이 근본 불가.** 모든 접근이 서기만 안정화. 원인:
1. 양발 同x → pitch 안식처(전후 지지 폴리곤) 부재.
2. 단일지지 진입 = 즉 텀블(컨트롤러가 0.1s 내 발산 못 잡음).
3. 부유 base 실행 = whole-body 제어 필수(ZMP 워커도 WBC 없이는 실행 불가).

## 5. 배포 & 다음 단계

### 배포 (확정)
**1점(점발) 보행 · 2점(평발/박스) 서기 역할분담.** C++ 배포 데모 무결(모든 실험 env-gated·별도 파일).

### 강건 2점 보행 = RL (추후)
- 모델기반은 데이터 생성(교사)·RL이 marginal 단일지지의 좁은 마진 운용. D1 자신도 NMPC→AMP RL 배포 방식.
- **남긴 자산(RL/WBC 출발점)**: D1 컨트롤러(서기 안정·실시간), pitch-rate 댐핑, box foot(CoP 마진), stagger(전후 폴리곤), **DCM 플래너**(WBC 붙이면 실행 가능).
- RL 소스 공급 시 착수.
